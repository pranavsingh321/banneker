All Architecture Decisions
DEC-001
Distributed Compute Orchestration
Three-process architecture: nova-compute, nova-conductor, nova-scheduler as separate daemons via RPC.
DEC-002
Two-Layer Data Model
SQLAlchemy ORM with Shadow tables wrapped by oslo.versionedobjects for API-level versioning.
DEC-003
REST API with Microversioning
WSGI REST over JSON with X-OpenStack-Nova-API-Version header (base 2.1, current 2.104).
DEC-004
Default Virtualization Driver
Libvirt (KVM/QEMU) as default; VMware, ZVM, Ironic via Stevedore pluggable drivers.
DEC-005
Horizontal Scaling via Cells v2
Cell0 metadata database + Cell1+ with independent DB, conductor, and compute hosts.
DEC-006
Concurrency Model
Eventlet green threads as default, with native Python threading fallback.
DEC-007
Authorization Framework
oslo.policy with 56 policy modules for fine-grained RBAC enforcement at API endpoints.
DEC-008
Pluggable Scheduler Filters
19 scheduler filters and weight plugins via Stevedore entry points.
DEC-009
Privilege Separation
oslo.privsep with oslo-rootwrap isolates privileged host operations from untrusted API code.
DEC-010
Messaging Transport
oslo.messaging with RabbitMQ via Kombu — RPC between API, scheduler, conductor, and compute.
DEC-011
Build Request Coordination
Scheduler → Conductor → Compute RPC chain with cursive state machine and TooZ locks.
DEC-012
Modular Configuration
48 config modules via oslo.config entry point with INI-style nova.conf.
